1 نظرة عامة — كيف يعمل النظام؟

المحفظة الرقمية ليست "تطبيقاً واحداً" — بل **نظام موزّع** من طبقات منفصلة لكل منها مسؤولية واضحة. الفكرة الأساسية:

📱 Flutter (الواجهة)

ما يراه المستخدم: شاشات، أزرار، عرض الرصيد. لا يحتفظ بالمفاتيح الخاصة ولا يتصل بالبلوكشين مباشرة.

🔗 REST API (الجسر)

قناة اتصال آمنة بين التطبيق والخادم. كل طلب موقّع بـ JWT Token.

🔴 Laravel (العقل)

منطق الأعمال: حسابات، أرصدة، معاملات، صلاحيات، تدقيق. يتصل بالبلوكشين وقاعدة البيانات.

🗄️ البيانات + البلوكشين

PostgreSQL للسجلات + Redis للطوابير + TronGrid للـ USDT على شبكة TRON.

مبدأ ذهبي: Flutter يعرض فقط — Laravel يقرر فقط — البلوكشين ينفّذ فقط. لا تضع منطق مالي أو مفاتيح خاصة في تطبيق Flutter أبداً.

3.2 الوحدات (Modules) ومسؤولياتها

🔐 Auth Module

  • تسجيل / دخول / خروج
  • JWT Tokens + Refresh Token
  • 2FA (TOTP)
  • استعادة كلمة المرور
  • تعليق الحساب

💼 Wallet Module

  • إنشاء محفظة USDT (عنوان TRC-20)
  • إنشاء حساب USD داخلي
  • عرض الرصيد المتاح
  • QR Code generation

💸 Transaction Module

  • إرسال USDT (سحب)
  • تسجيل إيداع USDT (وارد)
  • تحويل USD داخلي
  • سحب / إيداع USD
  • تقدير الرسوم

📒 Ledger Module (USD)

  • دفتر محاسبي مزدوج القيد
  • كل حركة: debit + credit
  • الرصيد = مجموع القيود
  • لا يُعدَّل الرصيد مباشرة أبداً

⛓️ Blockchain Module

  • الاتصال بـ TronGrid API
  • مراقبة عناوين الإيداع
  • توقيع وإرسال معاملات USDT
  • التحقق من تأكيدات الشبكة

👨‍💼 Admin Module

  • إدارة المستخدمين
  • اعتماد إيداعات USD يدوياً
  • تقارير وإحصائيات
  • ضبط الحدود والرسوم
  • Audit Log

5.4 المصادقة (Authentication Flow)

  1. تسجيل الدخول: Flutter يرسل email + password → Laravel يتحقق → يُرجع access_token + refresh_token
  2. تخزين آمن: Flutter يحفظ الـ tokens في flutter_secure_storage (مشفّر على الجهاز)
  3. كل طلب: Dio Interceptor يضيف Authorization: Bearer {token} تلقائياً
  4. انتهاء الصلاحية: عند 401 → Flutter يستخدم refresh_token → يحصل على token جديد → يعيد الطلب
  5. قبل الإرسال: Laravel يطلب 2FA أو كلمة مرور إضافية لعمليات السحب

7 مسار USDT — من الإيداع للسحب (Backend Flow)

7.1 استقبال USDT (Deposit)

  1. المستخدم يحصل على عنوانه — Laravel يولّده من HD Wallet ويخزنه في wallets
  2. مرسل خارجي يحوّل USDT — المعاملة تدخل شبكة TRON
  3. Deposit Listener — Job يعمل كل 15–30 ثانية عبر TronGrid API يفحص العناوين
  4. اكتشاف معاملة جديدة — يُسجَّل في transactions بحالة pending
  5. انتظار التأكيد — ≥ 1 confirmation على TRON
  6. تحديث الحالة — confirmed → تحديث balance → إرسال إشعار للمستخدم

7.2 إرسال USDT (Withdrawal)

  1. Flutter يرسل طلب — عنوان المستلم + المبلغ + 2FA
  2. Laravel يتحقق — رصيد كافٍ؟ حد يومي؟ عنوان صالح؟ حساب غير معلّق؟
  3. حجز المبلغ — pending_balance يزيد — الرصيد المتاح ينقص
  4. توقيع المعاملة — Hot Wallet يوقّع عبر TronService
  5. بث على الشبكة — الحصول على TX Hash
  6. تأكيد أو فشل — confirmed → إتمام | failed → إرجاع الرصيد المحجوز
مهم: لا تُرسل المعاملة للبلوكشين قبل حجز الرصيد في DB. وإلا قد يرسل مستخدم نفس الرصيد مرتين (Double Spend).

10 التراخيص والمتطلبات القانونية والتنظيمية

تنبيه قانوني مهم: تشغيل محفظة رقمية تحتفظ بأموال المستخدمين (Custodial) يُعتبر في أغلب الدول نشاطاً مالياً مرخّصاً. البدء بدون ترخيص يعرّضك لعقوبات قانونية وإغلاق الخدمة.

المتطلبالوصفإلزامي؟

11.2 خارطة طريق بناء الثقة

  1. كيان قانوني مسجّل — شركة في دولة تسمح بالنشاط. عرض اسم الشركة ورقم التسجيل في التطبيق والموقع.
  2. ترخيص VASP / مالي — أهم خطوة. اعرض رقم الترخيص في التطبيق والموقع الإلكتروني.
  3. KYC/AML مفعّل — تحقق هوية قبل تفعيل الإرسال. يربط كل محفظة بشخص حقيقي.
  4. تدقيق أمني (Security Audit) — شركة متخصصة تفحص الكود والبنية. شهادة مثل CertiK أو Hacken.
  5. Proof of Reserves — إثبات أن أموال المستخدمين موجودة فعلاً. مراجعة طرف ثالث دورية.
  6. تأمين الأموال — بوليصة تأمين ضد الاختراق أو Lloyd's of London للعملات الرقمية.
  7. شفافية الرسوم — عرض كل الرسوم قبل التأكيد. لا رسوم مخفية.
  8. دعم عملاء حقيقي — قنوات تواصل واضحة + وقت استجابة محدد.
  9. سياسات قانونية واضحة — شروط الاستخدام، سياسة الخصوصية، سياسة استرداد الأموال.
  10. نشر في متاجر رسمية — Google Play + App Store باسم الشركة المسجّلة.
